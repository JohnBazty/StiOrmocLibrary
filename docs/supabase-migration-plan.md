# Title

**MySQL → Supabase (PostgreSQL) conversion for STI Ormoc Smart Library**

## Why

The team needs a shared, hosted database so every buddy can use the same live data without depending on one person’s local MySQL install. Supabase gives us a managed PostgreSQL instance, connection strings, and a dashboard everyone can access. Converting the API and schema off local MySQL / `mysql2` is the prerequisite for that shared environment.

Product PDFs and `agent.md` historically name MySQL as the baseline; those docs are updated as part of this conversion so agents do not silently revert to MySQL.

| Triggers | Translate critical borrow/fine/lost/ink rules to PL/pgSQL; until each lands, API enforcement remains authoritative |

### MySQL → Postgres dialect map (implementation checklist)

| MySQL pattern | Postgres target |
| --- | --- |
| `?` placeholders | Adapter converts to `$1…$n` |
| `insertId` / `affectedRows` | Adapter: `lastval()` / `rowCount` (prefer `RETURNING` in new SQL) |
| `` `ident` `` | Unquoted or `"ident"` |
| `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` |
| `ENUM(...)` | `TEXT` + `CHECK` (or PG ENUM types) |
| `ON DUPLICATE KEY UPDATE` / `VALUES(col)` | `ON CONFLICT (…) DO UPDATE SET col = EXCLUDED.col` |
| `INSERT IGNORE` | `ON CONFLICT DO NOTHING` |
| `IF(a,b,c)` | `CASE WHEN a THEN b ELSE c END` |
| `DATE_ADD(x, INTERVAL n UNIT)` | `x + INTERVAL 'n unit'` |
| `CURDATE()` | `CURRENT_DATE` |
| `DATE_FORMAT(x,'…')` | `to_char(x, '…')` |
| `TIMESTAMPDIFF(SECOND,a,b)` | `EXTRACT(EPOCH FROM (b-a))` |
| `GROUP_CONCAT(x ORDER BY y SEPARATOR s)` | `string_agg(x, s ORDER BY y)` |
| `SUM(col='x')` | `COUNT(*) FILTER (WHERE col='x')` or `SUM((col='x')::int)` |
| `FOR UPDATE` | Keep (use direct Postgres connection, not transaction-mode pooler, for long txs) |
| `MEDIUMTEXT` / `LONGTEXT` | `TEXT` |
| `YEAR` | `SMALLINT` |
| `TINYINT` | `SMALLINT` |
| Triggers (`DELIMITER`) | PL/pgSQL functions + `CREATE TRIGGER` |

### Top risks (ranked)

1. Dialect volume across ~55 files (upserts, `GROUP_CONCAT`, date helpers).
2. `insertId` / tuple `execute` assumptions in writes and unit mocks.
3. Trigger + ENUM rewrite (borrow/fine/lost/ink).
4. Session upsert + notification `INSERT IGNORE` dedupe.
5. Supabase pooler vs `FOR UPDATE` transactions — prefer **session/direct** port `5432` for the long-lived API pool; pooler `6543` only if compatible.

### Tests

No live-DB integration tests. Unit tests mock `Pool.execute` with MySQL `insertId`/`affectedRows`. Migration tests assert MySQL `.sql` text — leave them pointing at the MySQL tree until Postgres equivalents exist.

-----                              ------
apps/web (Vite)                    apps/web (unchanged contracts)
    |                                  |

```text

9. Docs: agent.md, schema-context, getting-started, README
10. Smoke test + buddy connect
11. Status → built
```

### Adapter sketch

```ts
// pool.execute keeps mysql2 call shape for gradual migration
await db.execute('SELECT * FROM users WHERE email = ? LIMIT 1', [email])
// → pg: query('SELECT * FROM users WHERE email = $1 LIMIT 1', [email])
// → returns [rows, resultHeader] with insertId/affectedRows on writes
```
